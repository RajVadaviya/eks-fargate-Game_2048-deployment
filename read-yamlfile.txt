# 2048 Game Kubernetes Manifest Explanation

This YAML file deploys the 2048 game application on Amazon EKS using Kubernetes and exposes it publicly using AWS Application Load Balancer (ALB).

The manifest contains the following Kubernetes resources:

1. Namespace
2. Deployment
3. Service
4. Ingress

---

# Complete YAML File

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: game-2048
---
apiVersion: apps/v1
kind: Deployment
metadata:
  namespace: game-2048
  name: deployment-2048
spec:
  replicas: 5
  selector:
    matchLabels:
      app: 2048
  template:
    metadata:
      labels:
        app: 2048
    spec:
      containers:
      - name: app-2048
        image: public.ecr.aws/l6m2t8p7/docker-2048:latest
        ports:
        - containerPort: 80

---
apiVersion: v1
kind: Service
metadata:
  namespace: game-2048
  name: service-2048
spec:
  ports:
   - port: 80
     targetPort: 80
     protocol: TCP
  type: NodePort
  selector:
    app: 2048

---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  namespace: game-2048
  name: ingress-2048
  annotations:
    kubernetes.io/ingress.class: "alb"
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: ip

spec:
  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: service-2048
                port:
                  number: 80
```

---

# YAML File Explanation

---

# 1. Namespace

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: game-2048
```

## Purpose

A Namespace is used to logically separate Kubernetes resources.

All resources related to the 2048 application are deployed inside:

```text
game-2048
```

## Benefits

- Better organization
- Resource isolation
- Easier management
- Avoid naming conflicts

---

# 2. Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
```

## Purpose

Deployment manages application pods and ensures the desired number of replicas are always running.

---

## Deployment Metadata

```yaml
metadata:
  namespace: game-2048
  name: deployment-2048
```

### Explanation

- `namespace` → Defines where deployment will be created
- `name` → Name of deployment

---

## Replica Configuration

```yaml
replicas: 5
```

### Explanation

Kubernetes will maintain:

```text
5 running pods
```

If one pod crashes, Kubernetes automatically recreates it.

---

## Selector

```yaml
selector:
  matchLabels:
    app: 2048
```

### Explanation

Deployment manages all pods having label:

```text
app: 2048
```

---

## Pod Template

```yaml
template:
  metadata:
    labels:
      app: 2048
```

### Explanation

Each pod created by deployment receives label:

```text
app: 2048
```

This helps Service and Deployment identify the pods.

---

## Container Configuration

```yaml
containers:
- name: app-2048
```

### Explanation

Defines container name:

```text
app-2048
```

---

## Docker Image

```yaml
image: public.ecr.aws/l6m2t8p7/docker-2048:latest
```

### Explanation

This image contains the 2048 game application.

The image is hosted publicly on:

```text
Amazon Elastic Container Registry (ECR)
```

---

## Container Port

```yaml
ports:
- containerPort: 80
```

### Explanation

Application runs inside container on:

```text
Port 80
```

---

# 3. Service

```yaml
apiVersion: v1
kind: Service
```

## Purpose

Service exposes pods internally inside Kubernetes cluster.

Pods are temporary and their IP addresses change frequently.

Service provides:
- Stable networking
- Internal load balancing
- Communication between Kubernetes resources

---

## Service Metadata

```yaml
metadata:
  namespace: game-2048
  name: service-2048
```

### Explanation

Creates service named:

```text
service-2048
```

inside:

```text
game-2048
```

namespace.

---

## Port Configuration

```yaml
ports:
   - port: 80
     targetPort: 80
```

### Explanation

Traffic comes to Service on:

```text
Port 80
```

and forwards to container on:

```text
Port 80
```

---

## Protocol

```yaml
protocol: TCP
```

### Explanation

Service uses TCP networking protocol.

---

## Service Type

```yaml
type: NodePort
```

### Explanation

NodePort exposes application on worker node ports.

Example:

```text
80:32191/TCP
```

This allows external traffic to reach the application.

---

## Selector

```yaml
selector:
  app: 2048
```

### Explanation

Service forwards traffic to pods having label:

```text
app: 2048
```

---

# 4. Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
```

## Purpose

Ingress manages external HTTP/HTTPS access to Kubernetes services.

In this project:
- AWS Load Balancer Controller watches ingress
- Automatically creates AWS Application Load Balancer (ALB)
- Routes internet traffic to Kubernetes service

---

## Ingress Metadata

```yaml
metadata:
  namespace: game-2048
  name: ingress-2048
```

### Explanation

Creates ingress resource named:

```text
ingress-2048
```

inside:

```text
game-2048
```

namespace.

---

# Important ALB Annotations

Annotations provide additional instructions to AWS Load Balancer Controller.

---

## ALB Ingress Class

```yaml
kubernetes.io/ingress.class: "alb"
```

### Explanation

Tells Kubernetes to use:

```text
AWS Application Load Balancer
```

instead of other ingress controllers like NGINX.

---

## Internet Facing Load Balancer

```yaml
alb.ingress.kubernetes.io/scheme: internet-facing
```

### Explanation

Creates a public ALB accessible from internet.

---

## Target Type

```yaml
alb.ingress.kubernetes.io/target-type: ip
```

### Explanation

ALB directly routes traffic to pod IP addresses.

This configuration is required for:

```text
AWS Fargate
```

because Fargate does not expose node instances.

---

# Ingress Rules

```yaml
rules:
```

Defines routing rules for incoming traffic.

---

## Path Configuration

```yaml
path: /
pathType: Prefix
```

### Explanation

All traffic coming to:

```text
/
```

is routed to backend service.

---

## Backend Service

```yaml
backend:
  service:
    name: service-2048
```

### Explanation

Ingress forwards traffic to:

```text
service-2048
```

---

## Service Port

```yaml
port:
  number: 80
```

### Explanation

Traffic is forwarded to service on:

```text
Port 80
```

---

# Complete Traffic Flow

```text
User Browser
      ↓
AWS Application Load Balancer (ALB)
      ↓
Kubernetes Ingress
      ↓
Kubernetes Service
      ↓
2048 Application Pods running on Fargate
```

---

# What Happened in This Project

When this YAML file was applied using:

```bash
kubectl apply -f 2048_full.yaml
```

Kubernetes created:

- Namespace
- Deployment
- 5 Pods
- Service
- Ingress

Then:

AWS Load Balancer Controller detected the ingress resource and automatically created:

```text
AWS Application Load Balancer
```

Finally:

The 2048 game became accessible publicly through the ALB DNS endpoint.
